# Round 005：最终结论

## 模型结论

第三轮 1.7B 与第四轮 0.6B 已达到当前 SFT 数据与系统方案下的相近瓶颈。主集为 39/51 对 40/51，holdout 均为 21/24；这些差异不足以支持“0.6B 比 1.7B 更强”或相反的研究结论。

本项目正式认定：当前 0.6B/1.7B 路线的 SFT 已进入瓶颈，不再继续开展同路线的第六轮 SFT。这里的“瓶颈”不是指 SFT 理论上无法再提高任何样本，而是指在连续多轮定向补数据后，整体收益已经很小且不能稳定复现，继续投入的预期收益不足以覆盖能力回归和评测集过拟合风险。

项目最终采用双候选决策：

- 主模型：`r003-qwen3-1.7b-sft`。选择理由是用户倾向保留更大的容量上限，而不是因为评测已证明它显著更强。
- 高效替代：`r004-qwen3-0.6b-sft`。质量近似，CPU 推理更快、部署资源更低，适合成本或延迟优先场景。

两个 Adapter 都是有效产物，均保留在仓库中。第四轮 1.7B 因明确回退，不进入最终候选。

## 系统结论

评分器此前确实低估了模型：等价的日期时间追问被误判，“已确认服务时长”被误认为“已完成预约”。本轮修复后，评分更接近人工判断。但模型仍存在真实错误，不能把所有丢分归因于评分器。

剩余错误具有明显的确定性工程属性：相对日期计算、字段归一化、非法工具名和 JSON 协议。继续堆同类 SFT 数据已经出现收益递减和能力迁移，DPO 也不适合修复这些事实与协议错误。

### 停止继续 SFT 的依据

1. 训练结果不再单调提升：第四轮 0.6B 仅小幅改善，而第四轮 1.7B 从第三轮 38/51 回退到 35/51。
2. 训练 loss 正常下降，但评测能力没有同步稳定提升，说明继续拟合新增样本不等于总体能力继续增长。
3. 最终统一复评中，两个最佳候选主集只差 1 条、holdout 完全打平，表明继续围绕当前错误补样本没有形成清晰的能力突破。
4. 51 条主集已经被多轮用于错误分析和数据设计，继续据此训练会进一步增加评测集过拟合风险。
5. 已有强模型对照经验表明，更强基础模型无需本项目微调也能取得明显更好的效果。这说明当前任务并非不可学习，主要限制来自当前小模型的基础能力与容量；继续打磨同一批 0.6B/1.7B 的性价比有限。

### 不开展 DPO 的依据

DPO 适合优化多个合理回答之间的偏好，例如语气、简洁程度和交互策略。当前主要错误则是日期算错、非法工具名、JSON 协议错误、字段归类和状态继承错误，通常只有一个符合合同的答案。把这些错误制作成偏好对虽然可能改变输出概率，但不能可靠补足小模型的推理能力，也不能提供严格协议保证。因此，本项目认定 DPO 对解决当前主要问题没有足够价值，不进入下一轮 DPO。

## 下一步

1. 结束当前 0.6B/1.7B 的模型训练阶段，不启动 Round 006 SFT，不开展 DPO。
2. 在推理层加入合法工具白名单与 JSON Schema 约束，非法工具调用直接拒绝或重试。
3. 将相对日期交给确定性日期解析器，模型只识别原始时间表达和意图。
4. 增加字段归一化规则，区分通用服务“按摩”和真正的 `preferences`。
5. 上线前另建一套覆盖更多自然表达、业务边界和多轮路径的验收集；该集合只用于最终验收，不再据此改当前小模型训练集。
6. 如果未来仍希望显著提升纯模型能力，应重新进行基础模型选型，优先验证更强模型，而不是继续迭代当前 0.6B/1.7B Adapter。

最终判断是：当前模型训练阶段正式收口。SFT 已达到本项目现有小模型路线的工程瓶颈，DPO 与剩余问题不匹配；下一阶段转向完整推理系统优化，或者在需要更高纯模型能力时更换更强的基础模型。
