## 1. 本轮第一项工作

根据 Phase 05 的逐样本评估结果分析真实错误原因，再创建新的训练数据版本进行定向修复。流程为：

```text
修正评测误报
→ 用 eval-v0.2 重评现有模型
→ 逐条审核剩余失败
→ 建立错误分类与样本需求
→ 生成并审核 sft-v0.2
→ 重新训练 SFT
→ 在同一评估合同下比较
```

禁止直接把所有失败样本复制进训练集。每条失败必须先确认是模型错误、数据标签错误、评分器错误还是推理配置问题。

## 2. S001：定向重构 SFT 数据

### 2.1 多轮状态继承

针对 P001 增加状态差分样本：

- 只修改时间，保留时长、技师和偏好；
- 只更换技师，保留时间、时长和偏好，并清空待重新核实的技师性别；
- 只修改偏好，用新偏好替换旧偏好；
- 同时修改两个字段，其他字段保持不变；
- 用户明确说“其他不变”；
- 修改查询条件后使旧工具结果失效并重新调用工具；
- “技师不限”时允许 `technician_name=null`，不得继续追问技师姓名。

每个样本必须能明确说明：旧状态、用户本轮修改、保留字段、替换字段、失效字段和下一动作。

### 2.2 工具调用决策与参数

针对 P002 增加成对边界样本：

- 时间或时长缺失：输出 Final 并只追问缺失项；
- 时间与时长齐全：调用 `find_technicians`；
- 指定技师与条件搜索两种模式；
- 无普通偏好时保持 `preferences=[]`，不把“按摩”自动作为偏好；
- Tool Call 必须完整复制五个参数；
- 条件变化后重新查询，未变化的参数必须继承。

### 2.3 日期理解、提取与标准化

日期能力仍由模型完成，不改成外部公式替代。程序只负责生成正确标签和执行数据校验。

新增覆盖：

- 今天、明天、后天；
- 本周、下周、星期几和周末；
- 上午、下午、晚上与具体小时组合；
- 只有“明天下午”等模糊时段时输出 `start_time=null` 并追问；
- 多轮中从原日期改到新日期；
- 跨周、跨月和跨年；
- 多种 `current_time`，防止记忆固定日期；
- 正确日期与偏移一天、偏移一周、错误时段的近邻对照。

验收时单独报告日期标准化准确率，不与其他工具参数错误合并。

### 2.4 JSON 与 Schema 稳定性

针对 P003 增加以下严格输出模式：

- Tool Call 只能包含 `action`、`tool_name` 和 `arguments`；
- Final 必须完整包含规定字段；
- 禁止重复 JSON key、Markdown 包裹和解释文本；
- `duration_minutes` 必须为正整数或 Final 中的 `null`；
- `start_time` 必须符合格式；
- `missing_info` 只允许 `start_time` 和 `duration_minutes`；
- 非法枚举和 Tool Call/Final 字段混用作为错误对照。

### 2.5 回复与确认

- 技师已核实为 `available` 且用户明确确认：`confirmation=true`、`reply_type=booking_authorized`，回复预约成功；
- 技师可用但用户尚未确认：只能请求确认，不得提前声称成功；
- 用户拒绝或暂缓：`confirmation=false`、`appointment_paused`；
- 对 unavailable/not_found/no_match 的“知道了”需在统一 `confirmation` 字段定义后再修改数据。

训练中提供多种语义等价表达，避免模型只记住单一参考句。

## 4. S003：训练与对照顺序

### 4.1 为什么第一轮不同时修 SFT 和 DPO

SFT 负责建立基础能力，包括日期理解、槽位提取、多轮状态继承、动作选择、工具参数和 JSON/Schema 输出。DPO 适合在这些能力已经基本稳定后，进一步处理多个看似合理答案之间的复杂决策边界。

当前 SFT 仍存在日期错误、字段丢失、动作选择错误、工具参数错误和非法结构。如果此时同时修改 SFT 与 DPO：

- DPO 很难弥补尚未学会的基础能力；
- 新 DPO 的 chosen/rejected 可能继续继承旧 SFT 数据的问题；
- 最终指标变化无法判断来自 SFT 数据还是 DPO；
- DPO 可能掩盖或放大 SFT 的基础错误。

因此 Round 001 的范围固定为：

```text
修正评测合同
→ 定向重构 sft-v0.2
→ 重训 0.6B / 1.7B SFT
→ 对比旧 SFT 与新 SFT
→ 收集新 SFT 的残余复杂错误
```

DPO 不属于 Round 001 的训练范围。后续轮次只使用标签已确认、来自新 SFT 真实失败的高质量偏好对构建 `dpo-v0.2`。

第一轮建议采用以下顺序：

1. 在 eval-v0.2 上重评现有 0.6B 和 1.7B SFT 模型；
2. 构建并审核 `sft-v0.2`；
3. 使用相同训练参数重新训练 SFT；
4. 先比较 F16，判断数据修改效果；
5. 再比较同一权重的 Q4，隔离量化损失；
6. SFT 后仍存在的稳定错误才进入新 DPO 数据。

## 5. 建议的数据配比原则

本轮不先确定绝对样本数，先根据错误清单确定覆盖单元。每类覆盖单元至少包含普通表达、口语改写、多轮改口和近邻反例。新增定向数据不能挤掉已有简单场景，应保留旧数据回放以防能力回退。
