# Phase 06 Round 009：训练前后模型 APP 集成报告

## 实验目标

将 Phase 06 的最终模型接入双轨 APP，并形成可解释的训练前后对比：左侧固定为未经 SFT、未经低比特量化的 Qwen3-0.6B Base F16；右侧可切换 Round 004 最终 SFT 模型的 Q8_0 质量版与 Q4_K_M 低延迟版。

## 最终模型布局

| 轨道 | 模型 | 作用 |
|---|---|---|
| 左侧基准轨道 | `qwen3-0.6b-base-f16` | 原始 0.6B 基模，F16，不含 SFT adapter，用于展示训练前能力 |
| 右侧候选轨道 | `r004-qwen3-0.6b-sft-q8-quality` | 训练后质量优先版本 |
| 右侧候选轨道 | `r004-qwen3-0.6b-sft-q4-fast` | 训练后速度与体积优先版本 |

本地从 Hugging Face 缓存的原始 Qwen3-0.6B 权重转换得到约 1.5 GB 的 Base F16 GGUF。该大文件只保存在本地，不提交 Git。

## 本轮发现并修复的问题

### 1. llama-server 端口串模

旧 APP 遗留的 llama-server 占用了 18080/18081。新 APP 最初只检查端口是否健康，没有核验端口实际提供的模型，导致界面显示 Q8 或 Base F16 时，后端可能仍连接旧模型。

修复措施：

- Round 009 使用独立端口 19080/19081；
- llama-server 启动后读取 `/v1/models`，核对实际 GGUF 路径；
- 模型身份不一致时加载失败，不再静默复用错误模型；
- 最终实测左侧返回 Base F16，右侧返回 SFT Q8/Q4。

### 2. 对比目标不清晰

最初左右两侧分别放置 SFT Q8 与 SFT Q4，只能比较量化版本，无法直观看到 SFT 带来的能力变化。

修复后左侧固定 Base F16，右侧只展示训练后的 Q8/Q4，APP 的核心含义变为“训练前基模 vs 训练后部署模型”。

### 3. 相对时间纠正错误

输入“今天下午的按摩，时间2点钟”时，旧正则没有把相隔较远的“下午”和“2点”关联起来，错误纠正为凌晨 02:00，并触发“超出 Demo 日历范围”。

修复后会在相对日期与明确钟点之间寻找最近的时段词，正确得到当天 14:00。

### 4. 力度偏好未建模

Demo 原先只支持肩颈、精油、足部、泰式，无法处理“力气大”。本轮增加“力度较重/力度较轻”能力及“力气大、力度大、手法重、力度轻”等别名，并为 Demo 技师补充对应能力。

### 5. 唯一匹配后被模型改坏

工具已唯一找到王芳后，小模型仍可能生成非法的 `matched` 状态、空技师姓名或不存在的 `ask_technician_name`，导致成功查询被最终协议校验判为失败。

修复后，工具唯一匹配成功时由 APP 根据可信工具结果确定性生成 `available + confirm_available`，不再让第二次模型输出覆盖事实结果。

## 验证结果

- 时间纠正、力度别名、工具匹配和 APP 集成相关测试均通过；核心回归集为 26/26，通过扩展集为 20/20。
- `/v1/models` 实测左侧为 `phase06-round009-qwen3-0.6b-base-F16.gguf`，类型 F16，约 1.5 GB。
- `/v1/models` 实测右侧为 Round 004 SFT Q8_0 或 Q4_K_M，而非旧端口上的遗留模型。
- 人工输入“今天下午两点，60分钟，想找擅长肩颈的女技师”后，训练后模型完成参数提取、工具匹配并生成确认回复。
- 用户完成人工验收，Round 009 APP 集成通过。

## 最终结论

Round 009 已完成。APP 现在能真实比较未经训练的 Base F16 与训练后的 Q8/Q4，且模型名称、实际后端权重和端口身份一致。业务层已修复时间标准化、力度偏好和唯一工具结果落地问题。

本轮结果同时说明：模型负责语义理解，APP 负责确定性的时间归一化、工具事实和协议收口。量化只改变训练后模型的部署形态，不应与“是否经过 SFT”混为一谈。
